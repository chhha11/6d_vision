## 已完成的代码调整

可选的包围盒忠实使用完整估计旋转；轮廓、坐标轴和可选包围盒默认不做屏幕偏移（仅影响显示，不修改 3D 位姿）；需要回放旧数据时仍可显式设置显示偏移。`--box-roll-mode neutral` 只作为明确标注的显示选项，不参与位姿计算或精度验收。没有引入无法判断置信度的 `auto` 模式。

实时入口默认只显示绿色 CAD 轮廓和物体坐标轴，不显示黄色包围盒。轮廓线宽 2 px、坐标轴线宽 3 px，轴标签放大加粗。X 红、Y 绿、Z 蓝，Z 沿模型长轴；坐标原点位于 CAD 原点。轮廓和坐标轴默认使用模型投影位置，实际位姿和 XYZ 输出不变。按 **C** 可切换轮廓及坐标轴；`--show-box` 可选回黄色包围盒，`--no-pose-axes` 可单独关闭坐标轴。一次已保存帧上，5 次轮廓掩膜计算平均约 3.6 ms；这是本机离线计时，不代表实时平均性能。

实时入口默认保存最多 90 秒的原始 RGB 与逐帧位姿，位于该次 `tracking/diagnostics_<时间>/`：

- `rgb.avi`：未经叠框的 MJPG 视频。
- `poses.jsonl`：每个视频帧对应的真实时间、估计位姿、质量、有效状态，以及当时显示的位姿。跟丢时仍保留帧并明确标为无效。
- `metadata.json`：相机内参、畸变、图像尺寸、模型路径和逐帧真实时间。AVI 播放帧率只是名义帧率，回放分析应使用 `frame_timestamps_s`。
- 按 **S**：额外保存同一帧的无叠加 PNG、显示 PNG、位姿和标定 JSON；跟丢时也可以保存诊断，但不会将无效位姿写成可用初始化位姿。

录制从进入跟踪后开始，启动与初始化耗时继续参考现有 `startup_timing.json`、`initialization_timing.json`。视频和参考位姿均是算法输入/输出，不是独立真值。

## 官方开源方案比较

以下是 2026-11-03 对官方 README、CMake 配置及示例的检查，不是效果排名。2026-11-04 已完成 M3T 区域跟踪的本机编译与离线试验，详见后文；其余后端未实测。

| 方案 | 官方实现的相关能力 | 与当前项目的关系和限制 | 优先级 |
| --- | --- | --- | --- |
| DLR M3T / ICG | M3T 融合区域、深度和纹理；ICG 融合区域和深度。提供 CAD 模型、相机、检测器、细化器、跟踪器等组件。M3T 的 CUDA 特征支持为可选项。 | 首先试验 RGB 区域/轮廓跟踪，减少对少量纹理参考的依赖。仍需 Astra 输入适配和失踪后的全局重定位；局部跟踪器不等于任意姿态自动重新检测。 | 首选离线比较 |
| ViSP | 模型跟踪框架可结合边缘、纹理和深度。 | 可作为另一条几何跟踪路线，评估轮廓拟合、对称和遮挡行为。需要模型格式、初始化和参数适配。 | 备选 |
| FoundationPose | 已知 CAD 的 6D 位姿估计与跟踪，也支持另一种无模型流程。 | 官方环境需要 CUDA 版 PyTorch、PyTorch3D/NVDiffRast 和扩展编译；当前环境没有观察到 NVIDIA GPU，不优先安装这一整套依赖。 | 有合适 GPU 后再评估 |
| MegaPose | 面向新物体的 6D 位姿估计，使用 CAD 与学习模型。 | 可考察全局初始化/重新定位；不能据此假设其直接满足连续低延迟跟踪。官方 Docker 流程使用 NVIDIA 容器环境，需先核对算力成本。 | 全局定位备选 |

本机观察到 i7-13700H、约 31 GiB 内存、Intel 集显；`nvidia-smi` 不可用。CMake、g++ 和 OpenCV 4.5.4 开发包可用；Eigen3、GLEW、GLFW 和 OpenGL 的 pkg-config 查询未通过。M3T 官方 CMake 还要求 `xfeatures2d`，因此不能把 Python 的 `cv2` 已安装当成 C++ 后端依赖已齐备。没有更换现有 Python 环境或安装大模型权重。

若采用 M3T/ICG，先用同一段录像和同一初始位姿比较跟踪，再独立评估全局初始化与恢复。输入图像需按原标定去畸变，并给出与图像一致的相机矩阵；模型毫米与后端米单位必须显式转换。优先缓存轮廓模型，避免将模型生成时间计入每次进入跟踪的耗时。

建议比较：进入跟踪的总等待时间、错误位姿被纠正的时间、遮挡/出画后重新捕获时间、误捕获次数、CAD 轮廓贴合情况和处理延迟。没有独立真值时，不将重投影 RMS 当作毫米级绝对精度。

## 2026-11-04：M3T 区域跟踪离线试验

用户已确认实物尺寸正确。保留 150 mm / 95 mm CAD、现有标定和 12 px 显示补偿。

### 本机实现

- 官方源码固定于 `f02106186a1e756450226b3b793e309506817c58`，放在工作区 `third_party/3DObjectTracking`。未改动上游算法源码。
- `native/m3t/` 单独编译区域跟踪和所需公共组件，不编译需要 xfeatures2d 的纹理模块、相机 SDK 与官方示例。
- Eigen、GLEW、GLFW、GL 开发包约 1.9 MB 的下载放在 `third_party/m3t_deps/` 解包；没有 sudo 安装，没有更换 Python 环境。版本清单在该目录的 `manifest.json`。
- `core/evaluate_m3t.py` 读取原始 RGB、原标定和逐帧时间；先去畸变，保留相同 K；OBJ 顶点保留毫米，由 M3T 显式乘 .001 转为米。
- 每段只用首个有效同步位姿初始化：232806 的视频帧 1、233236 的视频帧 0。之后没有注入旧位姿，也没有用未来帧重新初始化。232806 的帧 0 只是无效 SEEDED，未用于新后端初始化。
- 输出恢复为相机坐标系毫米位姿。离线预览保留绿色轮廓、加粗 XYZ 轴和向下 12 px 补偿；诊断几何指标用未补偿位姿计算。
- 上述离线工具本身没有全局重新定位或合格位姿判定；实时接入见下方 2026-11-04 更新。离线输出明确写 `pose_validated=false`；API 成功不代表目标有效或精度正确。

## 2026-11-04：直接 3D 搜索、运动中交接与实时区域纠偏

区域后端已接入实时流程，但按原始时间戳回放的两段录像均出现丢失增加，因此默认关闭，保留 `--region-tracking` 供实验。相机预览与全图 CAD/参考特征的度量 PnP 搜索并行启动，不必先等 YOLO 找框。YOLO 只提供后台搜索区域，未检测到时仍继续全图 3D 搜索；侧置辅助轮流检查旋转图像。全图和区域搜索各自保留短时特征对应，避免交替搜索清空彼此的证据。

**缓慢运动时不等待静止**：RGB 位姿在工作线程求出后，通过双向光流和新的 PnP 更新到当前画面再采用；延迟的 YOLO 区域也用受校验的光流更新到当前帧。旧结果过期、光流不可靠或几何检查不通过时拒绝采用。静止门限仅保留在需要切换 RGB/深度流的旧深度兜底路径中，连续运动且参考不足时仍可能无法初始化。

`core/m3t_live.py` 与 `native/m3t/m3t_stream.cpp` 提供常驻、无相机占用的 M3T 区域建议。区域模型缓存并在后台准备；每帧输入原标定对应的 RGB，子进程去畸变并显式处理毫米/米转换。区域后端须先获得合格度量位姿才能启动，不能凭空完成未知视角的全局识别。建议通过当前分布式图像特征或当前 YOLO/长轴支持，以及 CAD 轮廓、运动与深度检查后，才能纠正位姿；仅有优化器成功或边缘贴合不算有效。新的检测区域与位姿冲突时转入验证状态，不用区域建议抹掉冲突。区域后端失败不会终止 RGB 恢复。

YOLO 的导入、预热与推理由 `core/detector_process.py` 独立子进程执行，外层后台线程只接收最新区域。这样隔离 Ultralytics 导入时修改 OpenCV 全局线程配置的副作用；修复前曾在并行参考匹配期间发生 SIGFPE，不能仅依靠 Python 异常捕获处理。独立进程有协议校验、超时及退出清理；预览与 3D 搜索线程不等待推理。

默认显示仍为绿色 CAD 轮廓与加粗 XYZ 轴，Z 为长轴。向下 12 px 只作用于绘制，不修改标定、模型尺度或输出位姿。仍使用原来的启动命令，无需安装另一个 Python 环境：
