## 1. 先录一段目前会失败的动态过程（约 3 分钟）

先录现状，再增加参考，方便后续对照。

```bash
/home/chhha/6d_vision/scripts/collect_tracking_evidence.sh motion --duration 180
```

程序沿用当前启动、深度回退、3D 跟踪和后台恢复流程，M3T 关闭，检测检查间隔为 2。录制从 RGB 打开后开始，包括没有成功初始化的搜索阶段。录制上限从会话开始计时；退出时会等待已经开始的后台任务安全结束。

按以下顺序操作即可，时间不必精确：

| 片段 | 操作 | 需要标记的时刻 |
| --- | --- | --- |
| 失败朝向，约 20–30 秒 | 一开始就摆最容易长时间不识别的姿态，完整露出并静止。先保留失败过程，再换到熟悉的易识别朝向 | 看得见按 V；一直未识别按 U |
| 慢速平移，约 30–40 秒 | 识别后，用约 8–10 秒向左移动约一个目标宽度，停 5 秒；再向右，停 5 秒；还可缓慢向上/下移动 | 开始移动按 M；停止按 T；发现轮廓偏离按 F |
| 慢速转向，约 30–40 秒 | 缓慢转向容易失败的另一面，再缓慢由直立变为倾斜/横置；每次停止后保持 5–10 秒，观察是否自己纠正 | 每段开始 N；移动 M；停下 T；偏离 F；未识别 U |
| 遮挡与返回，约 20–30 秒 | 完全遮挡或移出画面约 3 秒，再以失败朝向回到画面，保持 10 秒；有余时再用常见朝向重复 | 完全不可见 H；重新完整可见 V |

如果出现偏离或长时间不识别，**先保持现场 5–10 秒**，不要立即按 R 重置或 D 重取深度。程序提示抓取深度时，保持目标和相机静止，等跟踪窗口恢复后再移动。目标全程不识别也应保留这次录像。

快捷键是瞬时标记，不是持续按住或切换开关：

| 键 | 保存的含义 |
| --- | --- |
| V | 目标重新完整可见 |
| H | 目标完全不可见/完全遮挡 |
| U | 目标可见，但未识别 |
| F | 肉眼看到 CAD 轮廓明显偏离 |
| M / T | 开始运动 / 已经停止运动 |
| N | 开始下一段动作 |
| S | 原跟踪窗口中的同步截图功能，仅跟踪阶段可用 |
| Q / Esc | 提前结束并保存 |

标记由人的观察给出，存在反应延迟；记录的跟踪位姿也不是独立的 6DoF 真值。后续仍需结合原图判断偏移和恢复。

## 2. 补采静态参考（先完成最容易失败的两个朝向）

```bash
/home/chhha/6d_vision/scripts/collect_tracking_evidence.sh references
```

终端依次引导 10 个姿态：实际失败朝向、失败朝向稍微转动、直立正面/背面/左右侧、向左/向右横置、左右约 45 度倾斜。优先完成前两个和与你的失败场景最相近的姿态；无须强行摆出没有意义的姿态。

每个姿态的操作：

1. 摆好目标，在图像上用鼠标拖出紧贴整个目标的矩形框，完整包住目标但少带背景。
2. 移开手，保持静止至少 2 秒，然后按 **S**。从按 S 到深度抓取和检查结束，目标与相机都不要动。RGB 暂时关闭再恢复是切换到深度采集的正常过程。
3. 程序保存前后 RGB、五帧深度、标定副本，检查 CAD 拟合、前后静止程度和能否生成实际可用的参考特征。
4. 通过后显示绿色 CAD 轮廓供检查。轮廓应贴合物体整体边缘，位置和朝向不应明显偏离。确认后按 **A** 入库；明显不对按 **R** 重拍。复核默认沿用正常跟踪的显示纵向偏移（当前向下 12 像素），窗口会显示具体数值；按 B 可切换未补偿投影。两种投影都会保存，人工下移不修改测得的位姿，也不代表标定误差已经消除。
5. 自动检查失败不会入库，原因在终端。调整照明/距离、重新框选、保持静止后按 S 重试。同一朝向连续两次仍失败或轮廓总朝同一方向偏移，就按 **N** 暂时跳过，不要勉强按 A；原始失败数据仍然保留，可用于检查标定/深度偏差。

**Q** 保存并退出；再次指定相同 `--output` 可以接着采，已经接受的姿态会跳过，之前按 N 暂跳过的姿态会再次提示。使用终端打印的实际目录，例如：

```bash
/home/chhha/6d_vision/scripts/collect_tracking_evidence.sh references \
  --output /home/chhha/6d_vision/project/data/tracking/targeted_collection/实际目录名_references
```

完成第一组后，如果某个不同的实际工作距离也经常失败，可以重新运行 references，在该距离补采相关的失败朝向；其余姿态按 N 跳过。不要重复大量采同一个角度：当前加载器最多考虑最近 48 个通过筛选的捕获。

程序显示“已加入参考库”时，该样本已复制到 `project/data/tracking/live_depth_6dof/collection_时间戳/attempt_编号/`。**下次启动跟踪程序会自动加载**，当前已经运行的跟踪窗口需要退出重开。库中仍保留原有深度、静止、特征和几何门槛；通过采集检查不等于保证任意姿态都能识别。物体几何对称性造成的滚转/轴方向歧义仍然存在，人工检查也不能提供独立的完整姿态真值。

## 保存在哪里、交给我什么

每次启动会打印完整目录，默认在：

```text
/home/chhha/6d_vision/project/data/tracking/targeted_collection/
```

动态会话含：

- `continuous/rgb.avi`：未绘制覆盖图层的 RGB 输入，包含启动搜索。
- `continuous/frames.jsonl`、`metadata.json`：逐帧实际读取时间与视频帧索引。回放必须按时间戳，不能把 AVI 标称 FPS 当作真实采集速度。
- `continuous/events.jsonl`：人工标记、相机开关事件、跟踪阶段的位姿与状态，均关联到连续录像的帧索引。初始化前没有位姿是正常的。
- `live/`：原始初始化诊断、深度捕获和跟踪日志。
- `configuration/` 与 `session.json`：模型/标定副本、哈希和运行参数。

RGB 与深度切换时存在真实录像空窗，重开过程中的暖机帧也不会保存；时间戳会保留这个间隔。这里记录的是程序实际读取的帧，不承诺保存相机传感器产生的每一帧。程序退出后会完成 AVI 与元数据；正常操作请用 Q，尽量不要强制杀进程或断电。视频写入不可用会报错，不会静默继续假装录制。

静态会话另有 `references/姿态名/attempt_编号/`，保留通过和失败尝试的 RGB、深度、质量诊断及人工检查投影（`review_cad.png` 为显示补偿版，`review_cad_unshifted.png` 为未补偿版，`review_display.json` 记录偏移量）；`session.json` 记录已入库样本位置。

**采完把这三次会话的完整路径发给我即可**：补采前动态、静态参考、补采后动态。若只来得及采一部分，先发失败动态和最难识别的静态姿态；不要删掉失败样本。若文件仍在这台电脑，不用另行上传。

如自动选错摄像头，可在命令末尾加 `--camera 实际索引`。程序报错时保留终端消息和输出目录，特别是深度质量拒绝信息；不要为通过检查自行放宽门槛。
