# 目标从画面外缓慢进入时的 6DoF 初始化

运行方式保持不变：

```powershell
python -m core.live_depth_6dof
```

默认 RGB 优先入口现在针对“启动时无目标，之后缓慢进入并持续移动”处理以下情况：

- 允许 YOLO 检测框接触画面边缘，部分入场时即可搜索 RGB/CAD 对应点。原来边缘 3 像素的过滤会延迟整条 6DoF 入口。
- PnP 与跟踪器都将 CAD 投影裁剪到实际图像范围，再与可见检测框比较。宽高比、中心、尺度检查继续使用原门限，避免完整 CAD 框与半个检测框比较造成误拒绝。PnP 至少要求 35% 的投影包围框可见、12 个分布充分的内点，重投影 RMS 不超过 2.5 像素。
- 每次搜索建立独立的短时匹配状态。相邻检测帧的参考特征通过前后向光流跟到当前帧，与新匹配合并，最多保留六帧检测的历史，帧间隔超过 0.5 秒会清除。目标消失、位置突变、窗口尺寸变化或结果过期时清除历史。重合图像点不重复计入 PnP 内点。
- 不跨参考视图拼接 3D 点，每个视图单独求解；小匹配集继续要求第二参考位姿支持。累计的是已测量的特征点，输出仍是当前帧的 PnP 结果。没有复制旧位姿或用 2D 框外推一个 6DoF。
- RGB 求解成功后立即推进到最新图像并交给跟踪器，不经过静止确认。目标还贴着边缘时不自动切换深度，继续搜索 RGB，避免打断入场过程。

## 验证

`data/tracking/evaluations/slow_edge_entry_20261101/` 保存真实目标图像合成的入场回放。只移动目标像素，背景由原图去除目标后修补；前 24 帧没有目标，之后目标从左、右、上、下边缘进入并一直移动。检测器、特征匹配、PnP 和跟踪代码均实际执行。源图外观在参考库中，因此它验证此类视角的边缘入场和运动交接，不代表未见视角的泛化能力。

30 fps、每帧移动 1 或 2 像素的八组场景，对应图像速度 30、60 像素/秒；每四帧运行一次检测。新入口八组均在目标运动过程中解出位姿，相比旧边缘规则提前约 0.13–1.73 秒，成功帧总检测/求解耗时约 80–119 ms。首次定位时目标可见比例约 66%–100%。这个比例是上述样本的结果，不是对所有目标视角的承诺。

完整同窗口流程的 `live_handoff/report.json` 为四方向、60 像素/秒测试：

| 入场边缘 | 入场后首次 6DoF | 后续 TRACKING | 深度调用 |
| --- | ---: | ---: | ---: |
| 左 | 1.37 秒 | 30/30 帧 | 0 |
| 右 | 1.43 秒 | 30/30 帧 | 0 |
| 上 | 1.67 秒 | 30/30 帧 | 0 |
| 下 | 1.60 秒 | 30/30 帧 | 0 |

四组均无重定位请求，正常退出并释放采集对象。首次定位耗时包含物体从画面外移入、逐渐露出足够纹理的时间，不是单次 PnP 计算耗时。

自动回归覆盖边缘框、错误检测框拒绝、可见表面 PnP、两帧各不足十二点而合并后可定位、历史超时/跳变清除、部分入场不切深度及现有跟踪功能。全套 **165 项测试通过**（46.29 秒），代码编译检查通过。

## 使用边界

RGB 入口需要参考库中有可匹配的外观；光照、模糊、遮挡和缺少参考视角仍可能导致等待。物体只露出少量像素时，当前信息不足以稳定给出 6DoF，需要继续进入画面。本轮验证是合成运动，未让人实际缓慢移动相机或物体；真实场景中的入场速度和成功率仍需复测。
