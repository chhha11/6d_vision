# 端面朝向镜头时的 6DoF 初始化

目标水平旋转到端面更朝向 RGB/深度相机时，深度点云只显示约 90 mm 的圆盖，点云 PCA 的第一主轴是圆盖直径，不是能量单元 150 mm 的物理长轴。旧流程把这条直径当成长轴，ICP 得到偏转的姿态，随后被拟合质量门限拒绝；即使几何拟合成功，缺少可见平行棱条也可能使 RGB 交接拒绝该姿态。

现在的初始化在同一个窗口内保留原来的侧视假设，同时对满足“两个宽方向接近圆盖直径、第三方向较薄”的局部点云增加端面假设：

- 使用薄 PCA 方向作为 CAD 长轴，并以观测到的端盖平面设置初始平移；
- 用 CAD 的端盖直径、覆盖比例和径向覆盖检查端面证据；
- 仍要求 YOLO 框与 CAD 投影一致，并保留 RGB 采集前后的静止性检查；
- 端面没有足够的平行棱条时，不再强制要求 `observe_long_axis`，但没有端面几何证据的部分点云仍会被拒绝。

离线重放记录在 `data/tracking/evaluations/end_face_20261101/report.json`。12 组原来失败的端面深度样本全部通过几何拟合（fitness 1.0、RMSE 约 1.6–1.8 mm）；其中 7 组通过完整 RGB 交接，其余 5 组继续被原有采集运动检查拒绝。4 组普通侧视样本的几何结果保持一致。模型缓存准备好后，端面拟合、诊断文件写出和 RGB 交接的离线合计约 0.49–0.63 秒；此数值不含相机采集或 RGB 重开。

4 张通过完整校验的端面参考已加入 `data/tracking/live_depth_6dof/verified_end_face_20261101/`，来源记录在 `reference_provenance.json`，下次启动即会读入。`rgb_unseen_frames.json` 使用另外 7 张未作为参考的真实图像比较：RGB 定位通过数从 1/7 提高到 5/7，通过时单次参考定位耗时约 32–45 ms（不含 YOLO、相机和显示）。这些同场景结果不能代表所有角度、背景或连续视频的识别率。

`negatives/report.json` 比较了 7 组负样本在指定测试 ROI 中的结果：没有新增深度接受，新增参考库的 RGB 定位全部拒绝。其中 N005/N006 含部分遮挡目标，原流程与新流程都会接受其侧面深度拟合，因此这组检查不是“深度零误检”的证明。自动测试 186 项与 Python 编译检查通过。

端面分支需要深度点云覆盖足够大的圆盖。几何证据、RGB 框一致性或采集运动检查不通过时，程序继续拒绝该姿态并回到搜索。它并未解决端盖深度完全缺失、严重遮挡或所有新视角的问题；持续运动下的整体表现仍需实机验证。
