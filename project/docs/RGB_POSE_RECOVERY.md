# 竖放转侧置时的 RGB 位姿恢复

直播命令仍为 `python -m core.live_depth_6dof`，搜索、验证、恢复和深度重定位使用同一个窗口。

原跟踪环路只检查光流与 PnP 的点残差。点对应关系漂移后，低 RMS 仍可能伴随错误长轴；检测框检查只有 IoU 下限，横向目标和竖向投影交叉重叠时也可能被判为成功。

现在后台检查会匹配深度初始化对应的 RGB 目标特征，独立验证中心、长轴和尺度。两次具有充分空间分布且一致的匹配支持新的姿态后，系统从初始化参考恢复姿态并重新播种。角度验证使用无方向的轴线，180° 等价姿态不会触发纠正。

参考库准备完成后，跟踪器还在现有后台线程中进行独立 RGB/PnP 重定位。两次中心/长轴一致的结果通过检查后，将第二次结果的特征前推到最新画面，直接接回跟踪。姿态只相差等价滚转、或中心偏差不超过 12 mm 且长轴不超过 6° 时，不替换正常的光流对应；避免把参考匹配噪声不断引入框。

框的横截面使用统一的相机参考方向，不再跟随位姿绕长轴滚转，也不在接近竖直时切换参考轴。位置、距离和长轴方向仍正常更新。长轴正对相机时，使用固定的画面水平方向。

检测框还会检查宽高比。明确冲突时显示 `VERIFYING POSE`，XYZ 暂时无效；连续三次冲突且 RGB 参考不能恢复时，直播自动重采深度。原图没有检出时，后台轮流尝试 90°、180°、270°，每次最多追加一次推理。普通漏检仍交给光流/PnP 的持续丢失机制处理。

参考匹配与 YOLO 共用后台线程。匹配帧超过 0.5 秒、跨越过多帧或期间位姿移动过大时，结果被丢弃。无法可靠匹配新表面的视角变化仍需要深度重定位；这不是任意视角单目 6DoF 求解器。

`summary.json` 的 `rgb_recovery` 记录检查、建议、成功恢复、过期结果、深度请求及匹配耗时。检测框连续冲突时还保存不含绘制框的 `pose_verification_failed.png`，供分析真实目标图像。

新增 `rgb_relocalization` 记录独立 RGB/PnP 检查、候选、接受、无法前推到当前画面、保持原跟踪的次数。

验证结果位于 `data/tracking/evaluations/rgb_pose_recovery_20261101/`：

- `report.json`：在此次竖放 RGB 实拍图上仅旋转目标像素，保持背景不动。45°/90° 恢复轴线误差约 0.31°/0.10°。这是合成画面内旋转，不能代表实际放倒时的全部视角变化。
- `upright_to_sideways.png`：参考、错误竖框、恢复后横框的对照图。
- `replay_comparison.json`：五段原有真实运动录像的回放比较。终点中心误差没有增加，部分帧在验证期间暂停 XYZ 输出。

实际“从竖放放倒”仍需摄像头复测，以确认可见表面变化下走的是 RGB 恢复还是深度重定位。

## 2026-11-01 姿态调整与固定框方向

评测目录 `data/tracking/evaluations/pose_adjustment_20261101/`。在已知视角实拍图上，只对目标像素突变旋转 45°、90° 或放大 1.25 倍，旧版首次回到正确轴线/中心需 7 帧，修改后为 3 帧。该测试使用真实 YOLO/特征算法和同步测试执行器，帧数不能直接换算成实机耗时。

另注入“低 RMS 但三维对应整体偏转”的故障：18° 的长轴误差在旧版 60 帧中未恢复，独立 RGB/PnP 路径在第 3 帧校正并接回跟踪。这是人为注入的回归故障，非独立标定位姿真值测量。

新增框方向测试覆盖竖直附近的小幅倾角和横放到竖放的连续变化；真实新表面、遮挡和运动模糊仍需实机验证。参考库不足时原深度备用路径继续保留。

最终 183 项自动测试和 compileall 通过。四方向 60 px/s 合成移动入场复测均保持首次框选后的 30 帧有效跟踪，未触发深度采集或重识别。`fixed_box_comparison.png` 对比同一保存位姿下的新旧横截面显示，不代表姿态估计误差已被修正。
